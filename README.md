# Недельный отчет RECTOP

Веб-панель для недельного отчета: дашборды показывают месяцы, недели, графики и события, а вкладка `Админка` нужна для ежедневного ввода факта.

## Что есть

- `Все месяцы`: длинная недельная лента всех месяцев.
- `Обзор месяца`: KPI, выполнение плана, воронка, конверсии и недельные графики месяца.
- `Неделя`: детальный ввод/просмотр выбранной недели.
- `Админка`: ежедневный ввод `МСК / СПБ / Сообщения` x `Лиды / КВАЛ / Продажи`.
- `Сообщения`: отдельная витрина, не смешивается с городами.
- `События`: календарь внешних и внутренних факторов.

## Логика данных

- `Все` = `МСК + СПБ`, без сообщений.
- `МСК` = только Москва.
- `СПБ` = только Санкт-Петербург.
- `Сообщения` считаются отдельно.
- Новый месяц создается с планами по `МСК`, `СПБ`, `Сообщениям` и трем метрикам.
- Дневные планы распределяются автоматически по датам месяца.

## Подключение

1. Открыть Google Sheets.
2. Открыть Apps Script.
3. Вставить код из `apps-script/AppsScript.gs`.
4. Запустить `setupWeeklyReportService`.
5. Запустить `setWeeklyReportPassword("ваш-пароль")`.
6. Опубликовать Apps Script как Web App.
7. Добавить URL в переменные окружения:

```text
VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/.../exec
VITE_ADMIN_PASSWORD=ваш-пароль
```

Для GitHub Pages добавьте `VITE_APPS_SCRIPT_URL` в GitHub: Settings -> Secrets and variables -> Actions -> Variables или Secrets. Пароль админки в GitHub Pages не добавляйте: его нужно вводить в панели, иначе он попадет в публичный JS.

Если `VITE_APPS_SCRIPT_URL` не задан, панель работает в локальном fallback на демо-данных.

## Проверка перед публикацией

### Импорт источников Roistat

Кнопка `Roistat: источники` запрашивает API за выбранный период с дневными интервалами `interval: '1d'` и сохраняет результат в `Data_Daily`. Даты берутся из `dateFrom` каждого интервала. Это один запрос вместо запроса на каждый день; временные ошибки 429/5xx повторяются с теми же полями. Токен хранится только в Script Properties (`ROISTAT_API_KEY`), номер проекта — в `ROISTAT_PROJECT_ID`. Используются воронки `МСК АШ` и `СПБ АШ`; сообщения остаются отдельным отчетом. Формат запроса: [официальная документация Roistat](https://help-en.roistat.com/API/methods/analytics/).

Нераспознанное, другие источники и мессенджеры распределяются расчетно по всем распознанным источникам, включая Директ и Рек/кешбэк. Вес — исходное значение того же показателя за выбранный период в каждом месяце и городе: отдельно лиды, КВАЛ, продажи, выручка и расходы. Сначала методом наибольшего остатка фиксируется целочисленная доля каждого источника на весь период, затем эти доли распределяются по дням с сохранением дневных итогов. Так меняющийся объем нераспознанного не искажает месячные пропорции. Если базы нет во всем периоде, импорт сообщает об ошибке до изменения сохраненных данных.

Повторный импорт заменяет прежние строки Roistat за период (API, spreadsheet и report-24), сохраняя ручные данные. Маркер `[SOURCE_ATTRIBUTION=proportional-v1]` защищает импорт от повторного пересчета на экране и замены Директа помесячной таблицей. Это расчетная атрибуция, а не установленные источники отдельных заявок.

Строки источников записываются пакетами через `setValues`, а прежние импорты удаляются смежными диапазонами. Это сокращает число обращений к Google Sheets и позволяет импортировать месяцы в пределах времени выполнения Apps Script.

### Расходы по источникам

Месячные бюджеты загружаются из таблицы [ДРР](https://docs.google.com/spreadsheets/d/1tl-e_HAxxgGv24l19GaKaVz_6NYDuLqEwQH5esjER3o/edit) независимо от долгой загрузки аналитики брендов. Для сентября 2026 используются листы `МСК СЕНТЯБРЬ 26` и `СПБ СЕНТЯБРЬ 26`: столбцы E — Яндекс Карты, I — 2ГИС, K/L — название и бюджет другого источника, M — общий бюджет. Авито и реклама в метро сохраняются отдельно; остаток общего бюджета виден как «Прочие расходы». Итоги без названия бренда повторно не учитываются.

ДРР имеет приоритет над расходами Roistat и старыми данными брендов для того же месяца. В отчёте суммы обозначены как месячные бюджеты, без распределения по дням. В месяце без ДРР используются имеющиеся расходы Roistat или аналитики брендов. Если их тоже нет, выводится прочерк; условные 50 000 ₽ для SEO и Google больше не подставляются. В составном периоде известная часть помечается `*`, финансовые коэффициенты с неполным расходом не рассчитываются. На 15.10.2026 листов за октябрь 2026 в ДРР нет.

### Загрузка отдела продаж

Сервер читает `AmoCRM_Raw_Leads` один раз на запрос отчёта и использует тот же набор сделок для команды Дакоро и всего отдела. Соседние скалярные столбцы загружаются общими диапазонами, без `contactIds`, `customFieldsJson` и `rawJson`. При текущем порядке столбцов это два чтения вместо 66. Такой порядок устраняет тайм-аут интерфейса в 90 секунд на большом массиве сделок и сохраняет правила расчёта показателей.
